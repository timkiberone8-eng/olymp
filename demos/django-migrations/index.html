Зачем этот разбор и как им пользоваться

Вопрос разбора: когда описание Python становится настоящей таблицей? Пройди путь модели → файла миграции → SQL → таблицы и увидишь, на каком шаге меняются файлы, структура базы и товары.

  1. Прочитай действие и выбери прогноз: что оно изменит?
  2. Нажми «Показать результат» под прогнозом. Страница разыграет действие и объяснит результат.
  3. Сравни результат со своим прогнозом, посмотри блок «Что сейчас в файлах и базе», затем нажми «Далее» внизу.

Это тренажёр понимания, а не терминал: вводить команды здесь не нужно. Команды показаны как образцы для реального проекта. Кнопка копирования только копирует текст.

Почему первый migrate работает ещё до Product?
У admin, auth, contenttypes и sessions уже есть готовые файлы миграций в установленном Django. Команда migrate применяет все ещё не применённые инструкции из установленных приложений.
Встроенные миграции можно успешно применить ещё до описания Product. Таблицу товаров это не создаёт. В этой демонстрации встроенные таблицы свёрнуты в одну подпись, чтобы отдельно проследить catalog.
Число встроенных миграций зависит от версии и состава приложений. Для учебного маршрута предполагаем, что встроенные миграции уже применены до шага с Product.
Ручной SQL и Django: что осталось тем же?
CREATE DATABASE создаёт базу. CREATE TABLE создаёт таблицу внутри выбранной базы. ALTER TABLE меняет её устройство. INSERT добавляет строку.
Django генерирует SQL для PostgreSQL по операциям миграции. SQL остаётся механизмом изменения таблицы. Файл миграции — Python-код с описанием операций, а не таблица и не набор товаров.
Мы рассматриваем обычные миграции структуры. В Django существуют также миграции данных, но для обычного добавления товара они не нужны.
О модели, SQL и точности примеров
Приложение catalog добавлено в INSTALLED_APPS; соединение с catalog_db уже настроено. Используем стандартный BigAutoField для id. Поле in_stock имеет default=True, чтобы при добавлении поля существующие строки могли получить значение.
SQL и вывод сокращены для чтения; конкретное оформление и имена могут зависеть от версии Django. Миграции генерирует Django — перепечатывать и вручную редактировать их для этого урока не требуется.
